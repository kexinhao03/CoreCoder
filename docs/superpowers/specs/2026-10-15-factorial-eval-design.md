# ReliAgent reliability comparison Eval

Approved in conversation on 2026-10-15: six-step design, followed by user “开始执行”.

## Question and scope
Measure what retry and recovery improve, what they cost, and when a safe stop requires an operator. Preserve the existing 90/90 and 24/24 scenario contracts as regression evidence, not comparative reliability claims. Do not alter unrelated unfinished durable-loop fixes.

## Experimental controls
A=(retry off,recovery off), B=(on,off), C=(off,on), D=(on,on). All use the same production RuntimeExecutor/SQLiteStore, fixed task, approval policy, tool definitions, deadlines, and failure schedule. Enabled retry has max_attempts=3; disabled has max_attempts=1. Production eligibility rules still apply: do not enable retries on unsafe side effects just to manufacture a benefit. Fixed task inputs are evaluator-owned and identical across A–D. Disabled recovery means no automatic restart/resubmission of a task. A is not upstream CoreCoder.

E is original upstream CoreCoder at 069948d180cb0ceb1a6d7aafeb0e141c166a009d, available in local Git. Extract pristine source without modifying upstream implementation. Run in its own process/import path. E is only part of real-Agent comparison, not factorial attribution. Do not secretly add recovery or force replay to E. Record its unavailable persistence explicitly.

## Layers and workload
Mechanism layer: deterministic tool requests, real production Runtime and subprocess effects. Preparation tool fails once before success and is explicitly safe/idempotent; effect tool appends one fsynced independent record; final verification writes/checks a task artifact. This separates retry benefit from crash recovery benefit. Include normal and retry-only controls and two effect variants: independently queryable receipt and opaque outcome requiring human reconciliation.
Real-Agent layer: local existing Ollama qwen3:8b, same natural-language task and equivalent tools/input/settings for D and E. No model downloads. LLM selects calls. Capture tool/provider calls and approvals. Cases: normal, crash after effect before result persistence, crash after result before next inference. Preserve all model failures and fault misses. Every trial has a deadline. Never call a fixture a real LLM.

## Fault boundaries and delivery
Named boundaries: before_call_persist, after_call_persist_before_start, during_tool_execution, after_effect_before_result_persist, after_result_before_next_inference. For mechanism layer the last boundary is before task continuation, explicitly no inference in that layer. Distinguish exception, child_kill, runtime_kill (POSIX SIGKILL; platform labels for other termination). Parent supervisor waits for boundary handshake, injects fault, validates actual exit/action. Applicability is explicit: child_kill only when a child exists; not applicable combinations are excluded from eligible denominators but listed. A targeted boundary not reached is an invalid/missed-fault trial, not a passed trial. Supervisor records deadlines/errors and cleans only trial-owned children. No sleep-based race as fault proof. Resume is a new process using persisted production facts. Recovery may continue known-unstarted work, reuse completed work, or block unknown effects. No fabricated terminal statuses or guessed tool outputs.

## Independent observation and evidence
Per-trial directory persists beyond exceptions; write input/config/manifest before start. External fsynced marker and receipt file are distinct from Runtime SQLite. Supervisor observations determine effect count, duplicates and final artifact correctness, never Runtime SUCCESS alone. Persist stdout/stderr, injection handshake, exit status, timing, raw outcome, trace if available, DB including durable checkpoints (key separately/local only), trial/source/model fingerprints. Write evidence incrementally and atomically. Capture unknown result honestly. Do not put credentials or encryption keys in public reports. Failed and missed trials remain in raw output.

## Metric definitions
Primary task completion = externally valid artifact / all assigned repetitions, with automatic vs human-assisted completion separated. Recovery waiting is not automatic success. Duplicate side-effect rate = trials with >1 effect / side-effect trials, with observed/unknown counts; missing observation is unknown, not zero. Unsafe replay count = restarts of same logical side effect while its prior outcome is unresolved, observed by external dispatch/start log and durable knowledge boundary; do not infer it merely from duplicates. Human intervention = additional recovery reconciliation needed / all trials; routine consent approvals separate. No recovery is incomplete, not inherently a reconciliation request.
Recovery latency = supervisor monotonic elapsed restart launch to auto completion OR explicit safe block, separate distributions; full interruption-to-outcome also recorded. Unfinished samples censored, never treated as zero. Human waiting separate. Normal-path overhead: warmups excluded/labeled, per-trial total execution timing, SQLite write statements and committed write transactions instrumented without equating events to writes. Compare A–D as overhead of retry/recovery flags; compare D–E separately as combined implementation/provider overhead, disclose LLM noise.
Rates show numerator/denominator, invalid/unknown/censored counts, Wilson 95% interval; durations n, median, nearest-rank P95, min/max. Stratify by fault point/type/workload; do not hide differences in pooled totals. Paired A–D comparisons B−A,D−C (retry), C−A,D−B (recovery), D−B−C+A (interaction), labeled descriptive at small n. Only compute matched eligible observations. No significance claims from small samples.

## Execution size and acceptance
Mechanism default 10 repetitions per applicable group/workload/fault cell, interleaved deterministic order with recorded seed. Live default 5 per group/case (D,E), interleaved. Smoke runs smaller and explicitly labeled. Preserve complete raw denominators regardless of assertion success. Report must explain observed benefit/tradeoff, independent-effect evidence, failure cases and limits. Existing scenario assertions remain a separate regression section. Tests validate measurement/injection behavior, not increase a benchmark pass score.
