# ReliAgent 对照评测：收益、代价与失败边界

本报告把“场景断言是否符合预期”和“可靠性机制带来什么收益”分开。历史 90/90 Runtime、24/24 工作流检查保留为回归证据，不作为下述任务完成率。

## A–D：重试与恢复的机制对照

同一生产 Runtime、工具、审批策略、固定任务、截止时间和故障计划，仅改变重试与恢复。两个工作负载分别具有可独立查询的完成回执、不可确认的工具结果。每个有效组合重复 10 次，顺序由 seed=1729 交错排列，共 **1,040 轮**；880 次指定故障全部确认触发，零无效样本。子进程不存在时的终止组合明确列为不适用。

| 组 | 重试 | 恢复 | 任务自动完成 | 额外人工对账请求 | 重复副作用轮次 | 未确认操作自动重放 |
|---|---|---|---:|---:|---:|---:|
| A | 关闭 | 关闭 | 20/260（7.69%） | 0/260 | 0/260 | 0 |
| B | 开启 | 关闭 | 40/260（15.38%） | 0/260 | 0/260 | 0 |
| C | 关闭 | 开启 | 160/260（61.54%） | 40/260（15.38%） | 0/260 | 0 |
| D | 开启 | 开启 | 180/260（69.23%） | 40/260（15.38%） | 0/260 | 0 |

任务完成由独立效果日志和最终产物判断，不能由 Runtime 的 `succeeded` 代替。人工对账请求不算自动完成。本轮没有模拟人工提供结果，因此人工协助完成为零。A/B 没有发起恢复对账，但分别有 240/260、220/260 轮未完成；其零请求不能解释为完成任务所需人工成本更低。

在这一固定故障混合中，安全重试增加 **7.69 个百分点**完成率，恢复增加 **53.85 个百分点**，组合交互差值为零。每个对比有 260 个配对观测；这说明本任务中两种机制的收益可分离，不能据此宣称存在额外协同效应。重复执行确定性输入不是独立抽样的真实世界故障；报告中的 Wilson 区间仅描述本协议数据，不代表线上可靠性保证。

**没有观察到各组重复率差异。** 所有组均为零重复、零不安全重放，因此本实验支持“在提高完成率的同时未观察到重复效果”，不支持“相比 A 减少了重复副作用”或通用 exactly-once。

## 恢复成本和正常路径开销

| 组 | 重启至自动完成：n / 中位数 / P95 | 重启至安全阻断：n / 中位数 / P95 | 未完成的恢复样本 |
|---|---|---|---:|
| C | 140 / 1.182s / 2.509s | 40 / 0.396s / 0.806s | 40 |
| D | 140 / 1.172s / 2.458s | 40 / 0.392s / 0.759s | 40 |

未完成样本不填零、不并入成功恢复耗时。它们包括有副作用风险的工具在执行中抛错或子进程被终止后，原有策略不允许自动重试的情况；失败仍保留。

每组正常路径 n=20。A/B/C/D 耗时中位数分别为 **1.646 / 1.660 / 1.652 / 1.628 秒**，P95 分别为 **3.737 / 3.337 / 3.093 / 2.895 秒**；所有组均为 **84 条写入语句、49 次已提交写事务**。A 仍有持久化和审批，所以这些数值不能代表 Runtime 相比原始 CoreCoder 的总开销，也不能因 D 中位数略小便宣称 D 更快。

计时包含解释器启动、实际工具和保留证据的 fsync。运行期间主机还进行过真实模型校准及开发检查，存在主机负载波动；这不是隔离的生产微基准。数据库指标由实际连接跟踪得到，不是把审计事件数当作写入数。

## 失败案例与机制边界

- **暂时性准备失败**：仅 B/D 的安全、幂等工具允许自动重试；A/C 的 20 个重试对照任务全部未完成。
- **调用记录写入前/写入后尚未启动**：恢复组根据已保存的固定任务和调用状态继续，无恢复组保留未完成。
- **副作用已完成、Runtime 结果未保存**：有独立完整回执的任务经生产对账 API 自动核实；没有结果回执的任务停在人工对账，不能凭一个效果标记伪造完整工具返回值。
- **结果已保存、尚未继续任务**：恢复组复用原完成状态，不重新追加效果。
- **执行中异常、工具子进程终止**：与整个 Runtime 被 SIGKILL 分别统计；安全策略拒绝自动重试的失败不会包装成自动恢复成功。

## 真实 Agent 与原始 CoreCoder

真实模型比较使用已安装的本地 Qwen3:8b，LLM 自行选择工具和顺序。D_agent 是当前真实 durable Agent，**自动工具重试关闭**；它不是上表的完整重试 D。E 使用未修改的上游提交 `069948d180cb0ceb1a6d7aafeb0e141c166a009d`，不人为增加恢复或强制重复任务。

两组使用相同模型、工具模式、任务和审批策略。共同边界“Agent 已接收工具结果、下一次推理尚未发出”分别具有 D_agent 的持久结果、E 的内存结果。D-only 的持久化提交边界对 E 不适用，不能把组间不同案例混合后的总体百分比作为因果比较。

本轮共 **35 个真实模型试验、5 个明确不适用分配**；每个有效组/案例 n=5，零无效或未命中故障。10 个正常试验、25 次真实 SIGKILL。结果为 20 轮完成、10 轮未完成、5 轮等待人工对账，全部外部效果恰好一次，零观察到的不安全重放。

| 案例 | D_agent 自动完成 | E 自动完成 | D_agent 额外人工确认 | 说明 |
|---|---:|---:|---:|---|
| 正常执行 | 5/5 | 5/5 | 0/5 | 相同任务、模型和工具 |
| 副作用完成、结果未提交 | 0/5 | 0/5 | 5/5 | D 明确阻断，E 没有恢复；两者均未自动重放 |
| 已接收工具结果、下次推理之前 | 5/5 | 0/5 | 0/5 | D 复用原调用身份和完整已存结果，E 丢失内存上下文后停下 |
| D 的持久化提交之后 | 5/5 | 不适用 | 0/5 | 不用于组间共同案例比较 |

在三个共同案例各 n=5 的配对中，D_agent 为 10/15、E 为 5/15；差异来自已接收结果后的恢复，其他两个案例的完成率差值为零。这个结果支持真实 Agent 的持续执行收益，**不证明 Agent 自动工具重试收益**，也不证明降低重复率。原始 E 没有被人为添加重新提交任务的逻辑。

共同结果边界下，D_agent 重启至完成的中位数 **7.645s**、P95 **8.286s**（n=5）；D-only 持久化边界为 **7.568s / 8.224s**（n=5）。未知结果重启至安全阻断为 **0.525s / 1.038s**（n=5），人工等待未模拟，不计为完成恢复时间。

正常路径 n=5/组：D_agent/E 总耗时中位数 **18.856s / 18.199s**；模型耗时中位数 **18.070s / 17.593s**；扣除已观测模型耗时后的剩余中位数 **0.843s / 0.586s**。剩余耗时差约 **0.257s**，包含进程启动、工具、Runtime 和记录 fsync，不能称为纯 Runtime 延迟。D_agent 每轮有 **115 条写入语句、55 次已提交写事务**，E 为零 SQLite 写入。语句/事务指标不等同于磁盘页写入或 fsync 次数。模型占主导且 n=5，报告保留范围和 P95，不据此宣称稳定的生产性能比例。

**审计口径缺口也保留。** 20 个 D_agent Run 均保存了 Step 状态和完整工具事件，但 Agent Journal 没有另发 `step.created/started/completed` 等独立 Step 事件，旧 Trace 检查因此标出缺失。原始 Trace 标记没有被清除或补造。工具事件序列连续、外部效果与产物一致、10 个完成结果恢复案例的原调用身份和已保存结果不变；这与“独立 Step 事件审计完整”是不同结论。详见 [live-audit.json](live-audit.json)。

记录中的模型调用、原始工具参数/结果、审批、退出信号和效果均保留；其中加密数据库恢复需要本机私钥。机制表不能代替真实 Agent 证据。
